# 共同输入与资源

独立复刻以 [任务目录](../tasks/README.md) 为入口。包内含任务书、原始参考、执行边界、通用建议与空白规格模板。方法是可采用的建议，技术选择留给执行者。任务明确要求的条件由所有执行者共同遵守。

## 导出共同输入包

从仓库根目录运行（Python 3.11+）：

```bash
python3 scripts/catalog.py list --tasks
python3 scripts/catalog.py recreate "机械章鱼" --export local/input-packs/oc8-v2 --require-complete
python3 scripts/catalog.py verify local/input-packs/oc8-v2
```

把**同一包**交给每位执行者，从 `TASK.md` 开始。另给空输出目录；严格隔离时，执行环境只开放包和输出目录。已有代码、成品、测量、角色研究板与过程记录留在包外。包中的链接仅供识别出处或按约定取材。

## 补齐参考与校验

`recreate <case>` 显示任务和精确参考路径。省略 `--require-complete` 可以先导出一份取材清单，其 `missing_media` 列出缺失路径。按包内 `input.json` 将 `references/local/` 的原始媒体放入 `local/references/tasks/<case-id>/`（保留其余子路径），核对 SHA-256，换一个目录重新导出完整包。摘要不一致时，由组织者确认来源并冻结新版本。

`input_sha256` 是按预期文件路径和 SHA-256 计算的共同输入标识，取材清单与对应完整包具有相同标识。分发以 `verify` 通过为准。接收者可附 `--expect <input_sha256>`，与组织者另行发送的标识核对。旧记录若写的是 `inputs.json` 文件摘要，应按原口径解读。

输入内容和组织者附加指示都属于比较条件。资源边界改变、参考替换或任务要求变化时记录差异，并为下一轮统一条件。判断是否可比见[对照复刻约定](对照复刻约定.md)。
