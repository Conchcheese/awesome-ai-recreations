# 共同输入与资源

新复刻的共同输入是任务书、原始参考、目标与验收要求、通用工作思路，以及明确允许的资源。智能体自行决定几何、算法、架构、参数、镜头路径和制作顺序，尽量追求高质量结果。

| 输入侧：可以提供 | 成果侧：独立复刻不读取 |
|---|---|
| 需求、角色/产品版本、交付格式与质量目标 | 其他版本源码、可执行页面、模型及动画资产 |
| 冻结的原作图片/片段、来源与许可说明 | 复刻结果截图、成片、既有测量值与具体规格 |
| 通用制作思路、空白规格/记录模板 | 各模型工作过程、迭代记录、失败修复与调参结果 |
| 统一允许的第三方框架、工具与官方文档 | 仓库内含角色实现的 kit、导出器与专用工具 |

默认可使用通用第三方库与工具，例如 Three.js、浏览器、建模/渲染软件、FFmpeg及其官方文档；这不授权读取已有案例的项目代码。任务若限定框架、版本、运行环境或外部资源，所有实现采用同一约定。未限定处允许发挥，分别记录实际选择。

原始形态参考以输入清单为准；额外搜索原作、使用上游案例代码、成品模型或生成媒体补造参考，都属于输入条件变化，应先由任务明确允许并单独记录。公开教程或工具内的案例实现，不因使用同一框架就自动成为允许输入。

## 导出共同输入包

```bash
python3 scripts/catalog.py recreate "机械章鱼" --export local/input-packs/oc8
python3 scripts/catalog.py recreate optimus-prime-2007 --export local/input-packs/optimus-2007
```

给每个智能体相同的包，从 `TASK.md` 开始。`inputs.json` 逐项保存文件摘要与缺失媒体；只复制白名单文件，不递归复制参考所在目录。原始媒体不在新克隆中时，输入包仅带来源清单，须先补齐再进行视觉复刻；不能用现有成品补缺。

全仓共同输入位于 tasks/<case-id>/；原始参考已与成果目录分离。输入包保留其相对路径。未导出的链接不是额外授权，也不能沿旧参考目录查看邻近实现。冻结包后，各智能体在自己的输出目录产生测量、代码和过程。

严格隔离时，应只向新智能体开放输入包和独立输出目录，不给它整个成果仓库。导出工具控制交付文件，不证明执行者没有另外读取旧结果。

成果仍在仓库公开供体验、审阅和重建；只有任务明确要求衍生实现时才读取，并标注 derived。可复用经验经整理为不含角色答案的通用思路后，可在下一组实验中作为新的共同输入，不反过来改变旧实验的条件。
