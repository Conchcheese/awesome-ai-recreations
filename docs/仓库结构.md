# 仓库定位与结构

仓库通过不同智能体、AI 模型和工具，在同一案例、原始参考与目标要求下尝试复刻，展示实现效果并研究怎样稳定地产出高质量演示。成果、执行差异和可复用方法同时保留；共同输入与比较方式见[对照复刻约定](对照复刻约定.md)。

作品按系列组织，同一参考目标的不同实现作为案例版本；研究档案不计作成品。模型署名、实现来源和视觉目标分别说明。

## 目录地图

```text
README.md                 作品展厅，含截图、简介和在线演示
tasks/
  index.json              已就绪任务索引
  <case-id>/              共同任务书、输入清单和原始参考
catalog.json              已完成成果索引，记录版本、路径与命令
series/
  机械复刻系列/            机械案例与历史模型目录
  变形金刚系列/
    models/               按模型和案例组织新实现
    characters/           角色研究档案与待验证的拆分候选
    references/           参考研究板与来源
    publication.json      公开媒体路径、摘要与权利记录
docs/                     跨案例方法与维护指南
templates/                共用任务与资源模板
scripts/、tests/           索引工具、发布检查和测试
```

作品从[仓库首页](../README.md#案例展示)进入。各版源码、规格、过程、验证和导出命令保存在系列下的案例目录中。原始大文件、私密配置与生成文件留在被忽略的 `local/`、`private/`、`artifacts/`。

## 索引分工

| 索引 | 管什么 |
|---|---|
| [tasks/index.json](../tasks/index.json) | 可交给 Agent 的共同任务，允许先于成果登记 |
| [catalog.json](../catalog.json) | 已完成的案例和版本，使用 `task_manifest` 关联共同输入 |
| [变形金刚模型索引](../series/变形金刚系列/models/README.md) | 按执行模型找作品，包含保留原址的历史实现 |
| [character-library.json](../series/变形金刚系列/character-library.json) | 变形金刚角色研究档案与拆分候选 |
| [publication.json](../series/变形金刚系列/publication.json) | 变形金刚已公开的静帧、参考研究板和其他媒体 |

独立复刻从任务索引导出[共同输入包](共同输入与资源.md)。包内包含任务、参考、通用方法与资源约定。已有代码、测量和成品留在成果侧。

## 四种使用方式

1. **看作品**。在首页选择在线互动或巡览。下载仓库后也可打开离线 HTML，编码视频按各案例说明导出。
2. **重建已有版本**。运行 `python3 scripts/catalog.py show bumblebee-2007 --variant gpt-6-1-sol`，按查询结果进入对应案例目录。
3. **独立复刻**。把仓库地址和案例名发给 Agent，由它按 [AGENTS.md](../AGENTS.md) 导出共同输入包并独立实现。
4. **新增任务或成果**。按[贡献指南](../CONTRIBUTING.md)依次准备任务、验证成果和登记发布入口。

## 命名与兼容

变形金刚新成果采用 `models/<model-slug>/<case-id>/`。例如，大黄蜂位于 `models/gpt-6.1-sol/bumblebee-2007/`，其 CLI 版本 ID 为 `gpt-6-1-sol`。已发布路径保留，例如 Sol 擎天柱仍位于 `01-擎天柱-电影版/`，从 Sol 模型索引即可找到。模型署名与 Codex 等执行工具在成果记录里分开填写。

案例 README 提供成果、操作方式、精确运行命令、参考入口和已知差距；规格描述最终实现，验证说明只记实际执行的结论。完整诊断留 artifacts，原始提示词等有来源价值的材料保留并明确身份。资料链接不得指向新克隆缺失的本地文件。
