# 仓库定位与结构

仓库通过不同智能体、AI 模型和工具，在同一案例、原始参考与目标要求下尝试复刻，展示实现效果并研究怎样稳定地产出高质量演示。成果、执行差异和可复用方法同时保留；共同输入与比较方式见[对照复刻约定](对照复刻约定.md)。

作品按系列组织，同一参考目标的不同实现作为案例版本；研究档案不计作成品。模型署名、实现来源和视觉目标分别说明。

| 层级 | 内容与入口 |
|---|---|
| 仓库首页 | 两个系列的作品与使用入口；不承载任务流水 |
| `tasks/` | 全仓一致的共同输入；任务可先于任何成果存在 |
| `catalog.json` | 成果及版本的机器可读路径、命令数据源，以 task_manifest 关联任务 |
| `series/机械复刻系列/` | 机械案例；沿用已发布的模型版本目录和链接 |
| `series/变形金刚系列/models/` | 按模型组织新增实现；GPT-6.1 Sol 既有目录通过版本索引导航 |
| 系列 `characters/`、`references/` | 跨模型参考入口与研究资料，不是实现输出 |
| `docs/`、系列工作流、`templates/` | 跨案例方法、系列特有协议和新案例模板 |
| `scripts/`、`tests/` | 仓库索引与发布校验；案例工具放各自 `tools/` |
| `local/`、`private/`、`artifacts/` | 原始大文件、私密配置和生成中间件；不提交 |

输入侧只含共同的任务、参考、通用思路和资源约定；版本目录的代码、规格、测量、过程与成品都是输出侧。需要独立复刻时导出[共同输入包](共同输入与资源.md)，不把整个成果仓库当作输入。

## 四种使用方式

1. **看作品**：首页 → 系列 → 在线互动/巡览。离线 HTML 与编码视频是不同交付物。
2. **重建已有版本**：`python3 scripts/catalog.py show oc8 --variant gpt-6-1-sol`，按返回的目录、锁文件和命令运行。
3. **独立复刻**：把仓库地址和案例名发给 Agent；Agent 按 [AGENTS.md](../AGENTS.md) 导出共同输入包，在新目录实现，不把旧实现当输入。
4. **新增角色或模型**：按系列脚手架起草；已有运行成品和验证后再登记 catalog、系列/模型索引与 NOTICE。其他模型的已有成果不能代替指定模型调用。

## 命名与兼容

新模型目录用小写连接符，如 `gpt-6.1-sol`、`glm-5.3-flash`；案例目录写明角色及版本，如 `optimus-prime-2007`。文档文件名表达用途，日志不进入公开导航。已发布中文路径保留，避免仅为统一形式搬动全部作品、破坏 Pages 和外链。

案例 README 提供成果、操作方式、精确运行命令、参考入口和已知差距；规格描述最终实现，验证说明只记实际执行的结论。完整诊断留 artifacts，原始提示词等有来源价值的材料保留并明确身份。资料链接不得指向新克隆缺失的本地文件。
